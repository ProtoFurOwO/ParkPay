## 🚗 1. CAJONES con TARIFAS (INNER JOIN)

### 📍 Endpoint:
```
GET http://localhost:3000/api/cajones
```

### 🔍 Query SQL en el Backend:
```sql
SELECT 
  c.id_cajon,
  c.numero_cajon,
  c.ubicacion_piso,
  c.tipo,
  c.estado,
  t.id_tarifa,
  t.descripcion as tarifa_descripcion,
  t.costo_por_hora
FROM CajonesEstacionamiento c
INNER JOIN Tarifas t ON c.id_tarifa = t.id_tarifa
ORDER BY c.ubicacion_piso, c.numero_cajon
```

### ✨ Qué demuestra:
- **INNER JOIN** entre CajonesEstacionamiento y Tarifas
- Cada cajón muestra su tarifa correspondiente (normalización 3NF)
- Obtiene `costo_por_hora` y `descripcion` de la tabla Tarifas

### 📦 Respuesta Esperada:
```json
[
  {
    "id_cajon": 1,
    "numero_cajon": 101,
    "ubicacion_piso": "Piso 1",
    "tipo": "Normal",
    "estado": "Disponible",
    "id_tarifa": 1,
    "tarifa_descripcion": "Tarifa Normal",
    "costo_por_hora": "20.00"
  },
  ...
]
```

### 🎯 Para el Profe:
> "Esta consulta demuestra la **normalización**: en vez de duplicar el costo en cada cajón, usamos un INNER JOIN para obtener los datos de la tabla Tarifas."

## 🎫 2. TICKETS con múltiples JOINs (4 tablas)

### 📍 Endpoint:
```
GET http://localhost:3000/api/admin/tickets
```

### 🔍 Query SQL en el Backend:
```sql
SELECT 
  t.id_ticket,
  t.codigo_acceso,
  t.fecha_hora_entrada,
  t.fecha_hora_salida,
  t.estado,
  t.monto_cobrado,
  u.nombre AS usuario_nombre,
  u.apellido AS usuario_apellido,
  u.email AS usuario_email,
  v.placa AS vehiculo_placa,
  v.marca AS vehiculo_marca,
  v.modelo AS vehiculo_modelo,
  c.numero_cajon,
  c.ubicacion_piso
FROM TicketsEstancia t
JOIN Vehiculos v ON t.id_vehiculo = v.id_vehiculo
JOIN Usuarios u ON v.id_usuario = u.id_usuario
JOIN CajonesEstacionamiento c ON t.id_cajon = c.id_cajon
ORDER BY t.fecha_hora_entrada DESC
```

### ✨ Qué demuestra:
- **Múltiples INNER JOINs** en cascada (4 tablas)
- Relación: Tickets → Vehiculos → Usuarios
- Relación: Tickets → CajonesEstacionamiento
- Obtiene datos completos sin duplicación

### 📦 Respuesta Esperada:
```json
[
  {
    "id_ticket": 5,
    "codigo_acceso": "TICKET-1697456789-A3X9K2",
    "fecha_hora_entrada": "2024-10-16T10:30:00.000Z",
    "fecha_hora_salida": null,
    "estado": "ACTIVO",
    "monto_cobrado": null,
    "usuario_nombre": "Juan",
    "usuario_apellido": "Pérez",
    "usuario_email": "juan@example.com",
    "vehiculo_placa": "ABC-123",
    "vehiculo_marca": "Toyota",
    "vehiculo_modelo": "Corolla",
    "numero_cajon": 105,
    "ubicacion_piso": "Piso 1"
  }
]
```

### 🎯 Para el Profe:
> "Este JOIN demuestra cómo las **Foreign Keys** permiten relacionar 4 tablas diferentes para obtener información completa de un ticket, mostrando datos del usuario, vehículo y cajón sin redundancia."

## 👥 3. USUARIOS con VEHÍCULOS (LEFT JOIN)

### 📍 Endpoint:
```
GET http://localhost:3000/api/admin/usuarios
```

### 🔍 Query SQL en el Backend:
```sql
SELECT 
  u.id_usuario,
  u.nombre,
  u.apellido,
  u.email,
  u.telefono,
  u.es_admin,
  u.fecha_registro,
  COUNT(v.id_vehiculo) as total_vehiculos
FROM Usuarios u
LEFT JOIN Vehiculos v ON u.id_usuario = v.id_usuario
GROUP BY u.id_usuario
ORDER BY u.fecha_registro DESC
```

### ✨ Qué demuestra:
- **LEFT JOIN** (incluye usuarios sin vehículos)
- Función de agregación **COUNT** con JOIN
- **GROUP BY** para contabilizar vehículos por usuario

### 📦 Respuesta Esperada:
```json
[
  {
    "id_usuario": 1,
    "nombre": "Juan",
    "apellido": "Pérez",
    "email": "juan@example.com",
    "telefono": "5551234567",
    "es_admin": false,
    "fecha_registro": "2024-10-15T20:30:00.000Z",
    "total_vehiculos": "2"
  },
  {
    "id_usuario": 3,
    "nombre": "Admin",
    "apellido": "Sistema",
    "email": "admin@parkpay.com",
    "es_admin": true,
    "total_vehiculos": "0"
  }
]
```

### 🎯 Para el Profe:
> "El **LEFT JOIN** es importante aquí porque queremos mostrar TODOS los usuarios, incluso si no tienen vehículos registrados. Un INNER JOIN excluiría usuarios sin vehículos."

## 🚙 4. VEHÍCULOS con USUARIOS (INNER JOIN)

### 📍 Endpoint:
```
GET http://localhost:3000/api/admin/vehiculos
```

### 🔍 Query SQL en el Backend:
```sql
SELECT 
  v.id_vehiculo,
  v.placa,
  v.marca,
  v.modelo,
  v.color,
  u.nombre AS propietario_nombre,
  u.apellido AS propietario_apellido,
  u.email AS propietario_email

JOIN Usuarios u ON v.id_usuario = u.id_usuario
```

### ✨ Qué demuestra:
- **INNER JOIN** simple entre Vehiculos y Usuarios
- Foreign Key `id_usuario` relaciona ambas tablas
- Obtiene datos del propietario sin duplicar información

## 💰 5. TARIFAS con CAJONES que las usan (LEFT JOIN)

### 📍 Endpoint:
```
GET http://localhost:3000/api/admin/tarifas
```

### 🔍 Query SQL en el Backend:
```sql
SELECT 
  t.id_tarifa,
  t.descripcion,
  t.costo_por_hora,
  COUNT(c.id_cajon) as cajones_usando_tarifa
FROM Tarifas t
LEFT JOIN CajonesEstacionamiento c ON t.id_tarifa = c.id_tarifa
GROUP BY t.id_tarifa
ORDER BY t.id_tarifa
```

### ✨ Qué demuestra:
- **LEFT JOIN** para incluir tarifas sin cajones asignados
- **COUNT** con agrupación
- Integridad referencial (RESTRICT en FK impide borrar tarifas en uso)

### 📦 Respuesta Esperada:
```json
[
  {
    "id_tarifa": 1,
    "descripcion": "Tarifa Normal",
    "costo_por_hora": "20.00",
    "cajones_usando_tarifa": "20"
  },
  {
    "id_tarifa": 2,
    "descripcion": "Tarifa Discapacitado",
    "costo_por_hora": "15.00",
    "cajones_usando_tarifa": "5"
  }
]
```

## 📊 Resumen de JOINs en tu Sistema

| Endpoint | Tablas Involucradas | Tipo de JOIN | Propósito |
|----------|---------------------|--------------|-----------|
| `/api/cajones` | CajonesEstacionamiento + Tarifas | INNER JOIN | Mostrar cajones con su tarifa |
| `/api/admin/tickets` | TicketsEstancia + Vehiculos + Usuarios + Cajones | INNER JOIN (×3) | Info completa de tickets |
| `/api/admin/usuarios` | Usuarios + Vehiculos | LEFT JOIN | Usuarios con conteo de vehículos |
| `/api/admin/vehiculos` | Vehiculos + Usuarios | INNER JOIN | Vehículos con datos del dueño |
| `/api/admin/tarifas` | Tarifas + CajonesEstacionamiento | LEFT JOIN | Tarifas con conteo de uso |

## 🎓 Para Explicar al Profesor

### 1. **INNER JOIN vs LEFT JOIN**
```sql
-- INNER JOIN: Solo registros que coinciden en ambas tablas
SELECT * FROM Cajones c
INNER JOIN Tarifas t ON c.id_tarifa = t.id_tarifa;
-- Resultado: Solo cajones que tienen tarifa asignada

-- LEFT JOIN: Todos los de la izquierda, aunque no coincidan
SELECT * FROM Usuarios u
LEFT JOIN Vehiculos v ON u.id_usuario = v.id_usuario;
-- Resultado: Todos los usuarios, incluso sin vehículos
```

### 2. **Múltiples JOINs en cascada**
```sql
-- Relacionar 4 tablas:
SELECT *
FROM TicketsEstancia t
  JOIN Vehiculos v ON t.id_vehiculo = v.id_vehiculo    -- Ticket → Vehículo
  JOIN Usuarios u ON v.id_usuario = u.id_usuario        -- Vehículo → Usuario
  JOIN CajonesEstacionamiento c ON t.id_cajon = c.id_cajon; -- Ticket → Cajón
```

### 3. **Beneficio de la Normalización**
Sin JOIN (❌ mal diseño):
```
Tabla Cajones:
| id | numero | tarifa_descripcion | costo_por_hora |
|----|--------|-------------------|----------------|
| 1  | 101    | Tarifa Normal     | 20.00          |  ← Duplicado
| 2  | 102    | Tarifa Normal     | 20.00          |  ← Duplicado
| 3  | 103    | Tarifa Normal     | 20.00          |  ← Duplicado
```

Con JOIN (✅ normalizado):
```
Tabla Cajones:                  Tabla Tarifas:
| id | numero | id_tarifa |      | id | descripcion   | costo |
|----|--------|-----------|      |----|---------------|-------|
| 1  | 101    | 1         | ─┐   | 1  | Tarifa Normal | 20.00 |
| 2  | 102    | 1         | ─┤───┘
| 3  | 103    | 1         | ─┘
```
